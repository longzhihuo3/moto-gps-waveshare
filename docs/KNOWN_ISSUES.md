# 已知问题与发布边界

本次公开的是 Waveshare 成品验证线的开发快照，不是验证通过的量产版本。

| 状态 | 问题 | 目前结论 |
| --- | --- | --- |
| 未关闭 | 离家后圆屏停留 `WAITING FOR PHONE` | BLE / iOS 后台状态恢复需继续定位；不是已经证明为手机没网。当前版本不保证锁屏长期保活 |
| 未关闭 | 临沂前往济南西站没有可选路线 | 需要复现并检查位置、网关请求/响应和上游服务状态；不能直接断言高德不支持跨城 |
| 待回归 | 真机路线与 App 预览不一致、出现绕路 | 路线选择传递已有逻辑与自动测试，但尚未完成对应跨城实车回归 |
| 待回归 | 快速转向时翻页/撕裂感 | 已有双缓冲、插值和 CO5300 TE 同步逻辑；实际流畅度、持续帧率与耗电仍需测量 |
| 未关闭 | CI 的 `GatewaySettingsUITests` 偶发抖动 | 模拟器辅助功能服务偶发 `kAXErrorServerNotFound`，与代码改动无关，重跑失败任务即过；已在 v13/v14/v15 三次复现 |
| 固有边界 | 静止时绝对北向 | QMI8658 只有加速度计和陀螺仪，没有磁力计。手机在包里时不能把手机机身朝向当作车头方向 |
| 固有边界 | 济南之外背景路网 | 内置 OSM 数据只覆盖济南；其他城市没有同等离线灰路/建筑覆盖，不代表路线 API 不支持该城市 |
| 固有边界 | **高德 iOS 导航 SDK 不透出限速** | 逐页核实官方文档：`AMapNaviLink`（规划结果）、`AMapNaviInfo`（实时导航）与 delegate 回调均无限速字段。限速只能来自 OSM maxspeed（iOS 摩托模式已接，best-effort）或网关同名管道（Android 手机 App） |
| 固有边界 | OSM 限速覆盖率 | 大城市主路 maxspeed 标注较好，小路/乡村路段可能缺失；缺失时手表不显示限速牌（SDK 日志输出 `osm speed limit unavailable`） |
| 固有边界 | 限速、建筑缺失 | 依赖真实数据覆盖，不补画虚构内容 |
| 未验收 | 电池续航、USB/电池组合关机、防水、抗振、骑行安全 | 成品开发板并非本项目认证的车规设备 |

## 已解决的关键坑（踩坑记录，避免重蹈覆辙）

以下问题均已修复并经真机验证，记录根因与解法：

| 问题 | 根因 | 解法 |
| --- | --- | --- |
| 搜索报「SDK 未初始化」 | 高德要求任何 manager 实例化前先调两步隐私合规 | `AMapSearchAPI.updatePrivacyShow/Agree` + `AMapNaviManagerConfig.shared()` 同名方法，Bootstrap 统一前置 |
| 搜索报 `INVALID_USER_SCODE` | SideStore 重签名会改写 Bundle ID，与高德控制台绑定的 ID 不一致 | 报错时直接显示本机真实 Bundle ID；到高德控制台改绑新 ID 后删重装即恢复 |
| 算路一直超时、成功回调不触发 | AMapNaviKit v11 改名了成功回调选择器（连续关键词链，Swift 导入器拆成不同参数标签），旧格式实现能编译但永不触发 | 按导入器改写后的 Swift 签名实现回调（骑行/步行/驾车各有差异，驾车成功回调用 `...With` 导入形式） |
| 驾车引擎编译报错一批 | DriveManager Swift 导入差异：参数标签、策略枚举保留前缀 `.drivingStrategySingleDefault`、`naviRoutes/naviRouteIDs` 是属性不是方法 | 按导入器实际生成的接口逐一对齐 |
| 并发规划可能串话 | 规划会话队列按“每次新建”处理，无身份标识 | UUID 身份化队列，完成/超时按 ID 匹配，旧会话结果丢弃 |

本机演示用公共 POI 附近的真实 OSM 几何，可检查画面和动作关系，但不能验收实时路况、
真实定位精度、后台 BLE、手机蜂窝网络切换或真实导航正确性。

调试 BLE 时先停车：确认 App 前台是否恢复、iOS 蓝牙/定位权限、圆屏连接状态、
协议握手是否完成，再比对网关健康检查（未部署网关时确认内嵌 SDK 的隐私合规与
Bundle ID 绑定）。不要用重启“偶尔成功”代替根因记录。
提交日志前删掉经纬度、设备 UUID、序列号、服务令牌等个人信息。
